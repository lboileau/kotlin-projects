# UX review 1 — first-time user

Date: 2026-09-20 · Branch: meal-app-frontend (PR #315) · Record only, not an agreed backlog

Method: driven live in Chrome at http://r1.localhost:3000 as brand-new user ux-r1@example.com, in my own tab (now closed). Window resize did not take effect (innerWidth stayed 1728), so I saw the centred desktop column; mobile-specific remarks are reasoned from layout/CSS. NOT exercised live: (a) the Share button — navigator.share is a function in this Chrome, so tapping it would open a native macOS share sheet that could block the browser for all three reviewers; share/join/members were reviewed from code (useSharePlan.ts, shareLink.ts, JoinPlanPage.tsx, EditPlanSheet) plus a live bad-token join; (b) draft review / Accept all / publish — URL import fails locally ("Couldn't reach that page"), so RecipeReview.tsx and RecipeDetailPage.tsx were read, not run. Everything else below was observed live. Data I created: user "[R1] Robin Firstrun", ingredients [R1] Tomato passata / Spaghetti / Basil, recipe "[R1] Tomato spaghetti", plan "[R1] Week of Sep 20" (4 recipes, 2 manual items [R1] Kitchen roll / [R1] Milk). No console errors seen, but console tracking only started at the very end of the session and the page was not reloaded, so that check covers none of the flow.

All file paths are relative to `camper/webapp/src/`.

## 1. Verdict

The bones are genuinely good: every sheet deep-links and survives reload, the keyboard-driven ingredient line entry is the best part of the app (picker → Enter → qty → Enter → back in picker), plan creation is one tap + Enter thanks to the "Sep 20" default name, and check-off is instant. But the first-run path has two dead ends and the payoff moment is undercut: the shopping list — the "aha" — greets a newcomer with "lettuce 0.17 whole", "salt 0.17 tsp", "1 pieces [R1] Basil". A newcomer reads that as "the maths is broken". The single change that would most raise the love factor: make the shopping list read like a list a human would write (round countable units up to whole numbers, friendly fractions, singular/plural units, and "bought 2 · need 1 more" when a plan grows) — suggestion 1. Second: remove the two "you have no plan" dead ends so a newcomer flows recipe → plan → list without ever being told to go somewhere else.

Tap counts (first run): sign-up 2 submits; first plan 2 taps; hand-made 4-line recipe ≈ 1 tap + typing (superb); recipe → plan 2 taps (could be 1); first shopping list from zero, using seeded recipes: New plan → Enter → Add recipes → tap, tap → Done → Shopping list = 7 taps, ~25 s. That's a good number — the problem is what the list then says.

## 3. Suggestions (ranked)

1. **Make shopping quantities human** — High — Shopping list; `lib/formatQuantity.ts`, `lib/shoppingRows.ts` `formatQuantityText` (line ~126), `pages/shopping/ShoppingRowItem.tsx`. Today: "lettuce 0.17 whole", "tomato ⅔ whole", "bell pepper ¼ whole", "canned tomato ¼ can", "salt 0.17 tsp", "pepper 0.13 tsp", "ground beef 0.71 lb", "1 pieces". Change: add `formatShoppingQuantity(quantity, unit)` used only by `formatQuantityText` (recipe pages keep exact values): (a) for countable units — whole, pieces, clove, bunch, can, slice — round UP to the next integer (0.17 whole → "1", 1½ avocado → "2"); (b) for tsp/tbsp/pinch below ¼, show "a pinch"/"¼ tsp" (round up to nearest ¼); (c) other units: round to nearest ¼ and use the existing glyphs, else 1 decimal (0.71 lb → "¾ lb"); (d) pluralise: "1 piece / 2 pieces", "1 clove / 3 cloves", "1 can / 2 cans", and drop the word "whole" entirely ("2 avocado" → show as "avocado ×2" or just "2"); (e) manual free-form rows: render no quantity line at all instead of "1" (`row.description` rows). Why: this screen is the product's promise; it must look trustworthy at first glance and be buyable in a shop. Effort: M.

2. **Kill the two "no plans" dead ends** — High — `pages/recipes/AddToPlanSheet.tsx` lines 93-97. Today: text "create one from the Plans tab first", no action. Change: replace with copy "No plans yet." and a primary button "Create a plan and add this recipe" that calls the create-plan mutation with the same default name NewPlanSheet uses (today's date) and servings = the recipe's baseServings, then `addRecipe.mutate`, then toast "Added to Sep 20" with action "Open" → `/plans/{id}`, then `sheet.close()`. Why: a newcomer browsing seeded recipes taps "+" first — that should be the fastest path to the aha, not a rejection. Effort: S-M.

3. **Guard unsaved recipes** — High — `pages/recipes/NewRecipePage.tsx` and `EditRecipePage.tsx`; `components/PageHeader.tsx` back link. Today: header back arrow (and browser Back, and tapping a tab) silently throws away name + all lines. Change: compute `dirty` (any field non-default or lines.length > 0); use react-router `useBlocker(dirty && !createRecipe.isSuccess)` and show a Radix `AlertDialog`: title "Discard this recipe?", body "You've added {n} ingredients. They won't be saved.", buttons "Keep editing" (default) / "Discard" (red). Additionally mirror the new-recipe form state into `sessionStorage` (`meal-planner.new-recipe-draft`, try/catch like the rest) and restore on mount, clearing on successful save — that also covers reload. Why: losing a hand-typed recipe once is enough to make someone quit. Effort: M.

4. **Fix the character-dropping search fields** — High (bug with UX impact) — `pages/recipes/RecipesPage.tsx` lines 47, 103-104; `pages/ingredients/IngredientsPage.tsx` lines 22-26, 82. Today the input's `value` is the URL param and `onChange` calls `setSearchParams`; the router updates asynchronously so React resets the DOM value between keystrokes. Observed: typed "zzzz" → field and URL held "z"; typed "to" → "o". R2's tab showed `?q=%5D` after typing "[R2]…". On iOS this pattern also fights autocorrect/IME. Change: keep `const [text, setText] = useState(q)`; input is controlled by `text`; sync to the URL in a 200 ms debounced effect with `replace: true`; re-seed `text` when `q` changes from outside (Clear filters, back/forward). Effort: S.

5. **Stop creating "Other / pieces" ingredients by accident** — High — `pages/ingredients/NewIngredientSheet.tsx`, the inline create panel in `components/IngredientPicker.tsx`. Today defaults are Other + pieces and Enter submits, so fast users fill the shared, global ingredient table with junk categories (three reviewers did it within minutes), which in turn makes the shopping list's aisle grouping useless. Change: start Category as an unselected placeholder "Choose category"; Enter in Name moves focus to Category instead of submitting when it is unset; Add/Create stays disabled until a category is picked. Replace the Category `Select` with a wrapping row of 10 tappable chips (Produce, Dairy, Meat, …) — one tap instead of open-scroll-tap, and visible at a glance. Picking a category pre-selects a sensible unit (Produce→whole, Meat→g, Dairy→ml, Pantry→g, Spice→tsp, Bakery→pieces) which the user can still change. Keep the existing stickiness between consecutive adds. Effort: M.

6. **Explain and de-risk plan "Servings"** — High — `pages/plans/PlanDetailPage.tsx` servings row (~line 222) and recipe row badge (~line 252), `NewPlanSheet.tsx`. Today: "Servings 2" next to chips "serves 2/4/6"; a newcomer doesn't know the 6-serving tacos are being cut to a third (which is exactly what produces "0.17 lettuce"). Change: label "Cooking for" with value "2 people" and a caption under it: "Every recipe is scaled to this many servings." On each recipe row replace the "serves 6" badge with the effect: "scaled from 6 → 2" (or "serves 2" with no emphasis when equal). In NewPlanSheet add the same caption under the stepper. Effort: S.

7. **Show "need more" instead of silently unticking** — Medium — `pages/shopping/ShoppingRowItem.tsx`; data already there (`row.overallStatus === 'more_needed'`, `entries[].quantityPurchased/quantityRequired` from `lib/shoppingRows.ts` lines 31-33, 67). Today a row ticked at 2 cloves becomes a plain unticked "3 clove" when another recipe is added. Change: for `more_needed` render the checkbox in Radix's indeterminate state and the quantity line in amber: "Bought 2 · need 1 more". Tapping ticks it fully as today. Effort: S.

8. **Plan detail empty state should push "Add recipes", not "Shopping list"** — Medium — `PlanDetailPage.tsx` lines ~243-249 and BottomBar ~278. Today: small soft "Add recipes" top-right, grey sentence, and a full-width solid "Shopping list" button for a list that is empty. Change: when `recipes.length === 0`, render in the empty block a size-3 solid button "+ Add recipes" (SheetLink to="add") under copy "Pick the recipes you'll cook. The shopping list builds itself."; make the BottomBar button `variant="soft"` while empty. Once ≥1 recipe, current layout returns and the bottom button reads "Shopping list · {n} items" (count is in the shopping query if cached; otherwise omit). Effort: S.

9. **One-tap add when the target is obvious** — Medium — `pages/recipes/RecipesPage.tsx` `onAddToPlan` (line 191), `AddToPlanSheet.tsx`. Today "+" always opens a sheet, even with exactly one plan. Change: if the user has exactly one plan, "+" adds immediately (the mutation is already optimistic) and shows toast "Added to {plan}" with an "Undo" action (remove endpoint is idempotent); with several plans keep the sheet. After a successful add, swap that row's "+" for a check icon for the session so the list shows what's already in. Effort: M.

10. **Put form errors where the eye is, and clear them on edit** — Medium — `NewRecipePage.tsx` (error Callout rendered after LinesEditor, line ~185; `setError` only on submit), same pattern in `EditRecipePage.tsx`, `NewIngredientSheet.tsx`, `ImportRecipeSheet.tsx`. Observed: "Name is required." stayed visible through the whole recipe entry; "already exists" stayed while typing a new ingredient name; "Enter a URL." stayed after typing. Change: call `setError(null)` in each field's `onChange`; in the recipe form render the name error directly under the Name field (and `scrollIntoView({block:'center'})` + focus the offending field on failed submit, since Save lives in the header and the callout can be below the fold on a phone). Effort: S.

11. **Import: accept scheme-less URLs and offer a way forward on failure** — Medium — `pages/recipes/ImportRecipeSheet.tsx` line 102 and error block. Today `type="url"` makes the browser reject "bbcgoodfood.com/…" with a native bubble; on failure the user is stuck. Change: `type="text"` keeping `inputMode="url"`; on submit prepend "https://" when no scheme. Add a paste affordance: a soft "Paste" button inside the field that calls `navigator.clipboard.readText()` (hidden if unavailable). On IMPORT_FAILED / SCRAPE_FAILED add below the error a soft button "Add it by hand instead" → `sheet.close({ to: '/recipes/new?source=' + encodeURIComponent(url) })`, and have NewRecipePage seed `webLink` from that param. Also replace the header's bare download icon (`RecipesPage.tsx` line 75-83) with a labelled soft button "Import" with `Link2Icon` — a down-arrow reads as "download/export". Effort: S-M.

12. **Edit-ingredient Save should close** — Medium — `pages/ingredients/EditIngredientSheet.tsx` `handleSave` line 70-71. Change: after the toast, `sheet.close()`. (The add sheet rightly stays open for batch entry; an edit is a one-shot.) Effort: S.

13. **Quick-add feedback on the shopping list** — Medium — `pages/shopping/ShoppingPage.tsx` quick-add handler. Today new items appear off-screen at the bottom. Change: after the optimistic insert, `scrollIntoView({ block: 'nearest', behavior: 'smooth' })` on the new row and flash its background with a 600 ms `--accent-a4` fade (respect prefers-reduced-motion). Rename group "Misc" to "Extras" and sort it FIRST or directly above the input — and merge the visual confusion with "Other" by labelling that one "Other ingredients". Effort: S.

14. **Inline "Create ingredient" panel must come into view** — Medium — `components/IngredientPicker.tsx` (create panel). Observed: after Enter on "Create …", only the Name field was visible; Category, Unit and Create were under the tab bar. Change: on panel mount call `panelRef.current.scrollIntoView({ block: 'center' })`; drop the duplicated Name field (the picker input above already shows it, greyed) or collapse the picker input while the panel is open. Effort: S.

15. **Say something when a quantity is unparseable** — Polish→Medium — `pages/recipes/LinesEditor.tsx`. "abc" + Enter does nothing silently. Change: set `aria-invalid` and show under the field 'Use a number like 2, 1.5 or 1 1/2'. Give the quantity input a visible label or placeholder "Qty" — "1 1/2" as a placeholder looks like a pre-filled value. Exclude ingredients already on the recipe from the picker's default suggestions (they were listed first each time). Effort: S.

16. **Celebrate the first wins** — Polish — `NewRecipePage.tsx` after create: toast "Recipe saved" with action "Add to plan" (navigates to `/recipes/{id}/add-to-plan`). `ShoppingPage.tsx`: when progress reaches n of n, swap the progress row for "All done 🎉"-style copy without emoji if preferred: "Everything's in the basket." with a soft "Reset list" button. After registration, first Plans visit: change the empty-state heading to "Welcome, {first name}" once (flag in localStorage). Effort: S.

17. **Sharing needs one sentence of explanation** — Polish — `pages/plans/EditPlanSheet.tsx` Sharing section. Change: under "Sharing" add caption "Anyone with the link can join this plan, add recipes and tick off the shopping list." Rename "Copy summary" to "Copy as text" so it isn't confused with Share. (Inferred from the sheet as rendered; Share itself not tapped.) Effort: S.

18. **Shopping tab with a single plan should just open it** — Polish — `pages/shopping/ShoppingRedirect.tsx` `ChoosePlan`. Change: when `plans.length === 1`, `<Navigate replace>` to that plan's list (and set selected id). Effort: S.

19. **Affordances on tappable rows** — Polish — recipe detail lines (`RecipeDetailPage.tsx` `IngredientLineRow`): add a trailing `ChevronRightIcon` in `--gray-8` for owner-editable lines. `AddRecipeToPlanSheet.tsx` rows: trailing "+" icon that morphs into the existing "Added" badge; let a second tap on an "Added" row remove it (endpoint is idempotent) so mis-taps are fixable in place. `EditLineSheet.tsx`: autofocus the Quantity field, not the picker (the picker opens its dropdown over the form; quantity is the common edit). Move the recipe Delete out of the header next to Edit into the bottom of the Edit page. Effort: S each.

20. **Sign-in gives no reason to sign in** — Polish — `pages/sign-in/SignInPage.tsx` line ~76. Change subtitle to "Plan your meals, get one tidy shopping list. Enter your email to start — no password." Effort: S.

## 4. Quick wins (under an hour each)

4 (search inputs), 6 (servings copy), 7 (need-more row), 8 (empty plan CTA), 10 (clear errors on change), 12 (close on save), 13 (scroll to new item + rename Misc), 14 (scrollIntoView), 15 (quantity hint), 17, 18, 20, the pluralisation part of 1, the `type="text"` + https-prepend part of 11, and bugs B2/B3 below.

## 5. What's already great — do not lose

- Keyboard-only recipe line entry with focus returning to the picker; fraction parsing ("1 1/2" → 1½).
- Default plan name so "New plan → Enter" just works.
- Every sheet is a URL: reload and deep links restored /ingredients/new, /recipes/import, /plans/:id/edit exactly.
- Case-insensitive duplicate ingredient detection with the "Already in the list" chip.
- Sticky category/unit across consecutive ingredient adds; add sheet stays open for batch entry.
- Instant optimistic "Added" badges and check-offs; whole-row tap target; rows never reorder.
- Quick-add field keeping focus for rapid entry.
- Calm, honest not-found states ("Plan not found", "This link doesn't work") with a way back.
- Toast replacing rather than stacking.

## 6. Bugs

- **B1.** Search fields drop characters (see suggestion 4). Repro: /recipes, type quickly in "Search recipes". Seen: "zzzz" → "z". Same code shape in IngredientsPage.
- **B2.** Visiting a non-existent plan forgets the remembered plan. Repro: open a real plan's shopping list, then open /plans/00000000-0000-4000-8000-000000000000, then tap the Shopping tab → "Choose a plan to shop for." Cause: `PlanDetailPage.tsx` line 47-49 calls `setSelectedPlanId(planId)` unconditionally on mount, then lines 51-55 clear it because it now matches the not-found id (`ShoppingPage.tsx` lines 57-61 has the same shape). Fix: only set the selected id once the plan query has succeeded.
- **B3.** Bad join link shows a raw server message. Repro: /join/not-a-real-token → correct page state, plus red toast "No meal plan found for invite token: not-a-real-token". Cause: `useAcceptInvite` in `queries/plans.ts` line ~454 lacks `meta: { suppressErrorToast: true }` although JoinPlanPage renders its own error states.
- **B4.** Stale validation errors never clear until the next submit (NewRecipePage, NewIngredientSheet, ImportRecipeSheet) — see suggestion 10.
- **B5.** Import rejects scheme-less URLs via native validation while showing an unrelated stale error — see suggestion 11.
- **B6.** Minor: "Meal"/"Theme" selects on the recipe form have no "None" item, so once set they can't be cleared (`NewRecipePage.tsx` lines ~150-175; read from code, not exercised).
